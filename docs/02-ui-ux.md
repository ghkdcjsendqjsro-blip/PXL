# SUMINPIXEL UI와 사용자 경험 지침

이 문서는 화면의 배치, 시각 스타일, 조작 방식과 상태별 표시를 정합니다. 화면은 한국어로 만들고, 사용자는 회원가입 없이 이미지를 첨부하거나 글을 써서 픽셀 이미지를 만들 수 있습니다. 기능과 수치가 충돌하면 루트의 [PRD.md](../PRD.md)를 먼저 확인합니다.

## 2. 화면의 기본 방향

- 한 페이지 안에서 입력 → 생성 → 결과 확인 → 다운로드가 이어집니다.
- 밝은 연보라 배경 위에 흰 작업 카드를 두고, 제목과 테두리는 짙은 보라로 표시합니다.
- 픽셀 느낌은 제목, 아이콘, 테두리, 그림에서 표현합니다. 설명과 피드백 본문은 읽기 쉬운 일반 글꼴을 사용합니다.
- 메인 작업보다 장식이 먼저 보이지 않도록 구름·별 장식은 상단과 빈 공간에만 소량 배치합니다.
- 배경의 격자는 32px 간격의 아주 옅은 선으로 만듭니다. 카드 안의 본문 아래에는 격자를 넣지 않습니다.

## 3. 디자인 값

CSS의 `:root`에 아래 값을 변수로 정의하고, 컴포넌트마다 비슷한 색을 임의로 추가하지 않습니다.

```css
:root {
  --page: #f5f0ff;
  --surface: #ffffff;
  --ink: #281044;
  --muted: #655673;
  --primary: #5a2692;
  --primary-hover: #42186e;
  --pink: #f34eac;
  --mint: #a3efcc;
  --yellow: #ffe08a;
  --line: #4b286c;
  --soft-line: #d9cbe6;
  --error: #a2173a;
  --success: #176443;
  --focus: #135cbd;
  --color-paper: var(--page);
  --color-ink: var(--ink);
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 24px;
  --space-6: 32px;
  --space-7: 48px;
  --space-8: 64px;
}
```

| 항목 | 구현 값 |
| --- | --- |
| 본문 글꼴 | `system-ui, -apple-system, "Segoe UI", "Malgun Gothic", sans-serif` |
| 영문 로고·숫자 강조 | `"Courier New", monospace`; 자간 -0.04em, 굵기 700 |
| 기본 본문 | 16px / 줄 높이 1.6, `--ink` |
| 보조 설명 | 14px / 줄 높이 1.5, `--muted`; 12px 미만 금지 |
| 상단 큰 제목 | 데스크톱 48px, 모바일 32px / 줄 높이 1.2 |
| 구역 제목 | 24px, 모바일 22px / 굵기 700 |
| 작업 카드 | 흰 배경, 2px `--line` 테두리, 8px 모서리, 오른쪽 아래 4px 단색 그림자 |
| 일반 입력 | 흰 배경, 1px `--muted` 테두리, 6px 모서리, 안쪽 여백 12px |
| 기본 버튼 | `--primary` 배경과 흰 글자; hover는 `--primary-hover` |
| 강조 장식 | 핑크·민트·노랑은 배지와 장식에 사용; 노랑 위 흰 글자 금지 |
| 최소 조작 크기 | 버튼, 탭, 파일 선택, 라디오 선택 영역 모두 높이 44px 이상 |
| 키보드 초점 | 3px `--focus` 외곽선과 3px 간격; 기본 outline 제거 금지 |

보조 버튼은 흰 배경, 짙은 보라 글자와 테두리를 사용합니다. 비활성 상태는 색상만 바꾸지 말고 실제 `disabled` 속성과 비활성 이유를 함께 제공합니다. 텍스트 대비는 일반 글자 4.5:1 이상, 큰 글자와 조작 테두리는 3:1 이상인지 브라우저 검사 도구로 확인합니다.

## 4. 화면 구성과 문구

전체 콘텐츠는 최대 너비 1120px로 가운데 배치합니다. 왼쪽부터 읽고 위에서 아래로 내려가는 순서를 유지합니다.

```text
헤더: SUMINPIXEL                         [만들기] [피드백]
소개: 사진도, 상상도 픽셀로.
      이미지를 올리거나 원하는 장면을 적어 보세요.

┌ 입력 카드 ─────────────────┐  ┌ 결과 카드 ─────────────────┐
│ [이미지로 만들기] [글로 만들기] │  │ 나의 픽셀 이미지              │
│ 파일 선택 또는 프롬프트         │  │ 빈 상태 / 생성 중 / 결과      │
│ 픽셀 크기 · 색상 수             │  │ 1024 × 1024 PNG              │
│ [픽셀 이미지 만들기]           │  │ [PNG 다운로드] [다시 만들기] │
└─────────────────────────────┘  └─────────────────────────────┘

사용 방법: 1 입력 → 2 픽셀 설정 → 3 만들고 저장
피드백: 공개 안내 + 작성 폼 + 최신순 목록 + [더 보기]
푸터: SUMINPIXEL · 이미지 처리와 피드백 공개 안내
```

### 4.1 헤더와 소개

- 헤더 로고는 텍스트 `SUMINPIXEL`로 만들고 클릭하면 페이지 상단으로 이동합니다.
- `만들기`는 `#create`, `피드백`은 `#feedback` 구역으로 이동하는 실제 링크입니다.
- 소개 문구는 위 예시를 사용합니다. 긴 마케팅 설명이나 회원가입 버튼을 추가하지 않습니다.
- 작은 배지 `NO LOGIN · PIXEL STUDIO`를 표시할 수 있습니다. 로그인 없이 피드백을 남길 수 있다는 안내는 피드백 영역에도 제공합니다.

### 4.2 입력 카드

제목은 `픽셀 이미지 만들기`입니다. 처음에는 `이미지로 만들기` 탭을 선택합니다. 탭 사이를 이동해도 작성 중인 파일과 텍스트를 유지하지만, 생성 요청에는 현재 탭의 입력만 사용합니다.

| 입력 | 표시와 행동 |
| --- | --- |
| 이미지 탭 파일 영역 | `이미지를 끌어오거나 파일을 선택하세요` 문구, 파일 선택 버튼,`PNG, JPG, WEBP · 최대 8 MiB` 안내 |
| 선택한 이미지 | 파일명, 미리보기, `이미지 변경`과 `삭제` 버튼; 파일명은 긴 경우 줄바꿈 |
| 이미지 탭 보충 설명 | 제목 `원하는 느낌 (선택)`; 예시 `고양이의 무늬는 유지하고, 아늑한 게임 속 장면처럼` |
| 프롬프트 탭 | 제목 `어떤 이미지를 만들까요?`; 여러 줄 입력, 예시 `보라색 밤하늘 아래 작은 고양이가 앉아 있는 픽셀 카페` |
| 픽셀 크기 | 라디오 3개: `32 × 32 · 큼직하게`, `64 × 64 · 기본`, `128 × 128 · 섬세하게`; 기본 64 |
| 색상 수 | 라디오 3개: `원본 색상`, `16색`, `32색`; 기본 32색 |
| 생성 버튼 | `픽셀 이미지 만들기`; 처리 중에는 `만드는 중…`과 움직임이 적은 로딩 아이콘 |

픽셀 크기 아래에 `작은 숫자일수록 픽셀이 더 크게 보여요. 저장 파일은 모두 1024 × 1024 PNG예요.`라고 설명합니다. 32 × 32, 64 × 64, 128 × 128은 가로·세로의 실제 논리 픽셀 개수입니다. 색상 설정은 원본 유지 또는 최대 색 수 제한을 뜻하며, 모든 결과에 반드시 16개·32개의 색이 생긴다고 안내하지 않습니다.

이미지는 자르지 않습니다. 원본의 가로세로 비율을 유지한 채 1024 × 1024 정사각형 안에 맞추고 남는 부분을 흰색으로 채운다는 설명을 첨부 미리보기 아래에 표시합니다. 브라우저에서 파일을 먼저 검증한 뒤 방향을 보정하고 정사각형 PNG로 정규화합니다. 정규화한 파일은 2 MiB 이하, 서버에 보내는 전체 요청은 3 MiB 이하로 제한합니다. 이 값은 입력 원본의 8 MiB 제한과 별개입니다.

생성 버튼 근처에 `이미지는 AI 처리에 사용됩니다. 생성한 결과는 이 화면에서 내려받아 주세요.`라고 표시합니다. 실제 저장 정책은 [데이터와 피드백 문서](05-supabase-feedback.md)의 정책에 맞춰 문구를 최종 확인합니다. 결과가 원본과 완전히 같게 유지된다고 약속하지 않습니다.

### 4.3 결과 카드

- 제목은 `나의 픽셀 이미지`입니다. 미리보기 영역은 `aspect-ratio: 1`로 정사각형을 유지합니다.
- 빈 상태에는 작은 픽셀 그림과 `나만의 픽셀 이미지가 여기에 나타나요.`를 표시합니다.
- 생성 중에는 `픽셀을 만들고 있어요. 잠시만 기다려 주세요.`라고 표시합니다. 실제 서버 진행률이 없으므로 32%, 78% 같은 임의 숫자를 만들지 않습니다.
- 성공하면 결과 이미지와 `1024 × 1024 · PNG`를 표시하고 다운로드 버튼을 활성화합니다.
- 결과 이미지에는 `image-rendering: pixelated`를 적용합니다. 실제 PNG도 정수 배율 최근접 확대 방식이어야 하며 CSS만으로 픽셀 이미지를 흉내 내지 않습니다.
- 성공 후 픽셀 크기와 색상 수를 바꾸면 메모리에 보관한 AI 결과로 브라우저에서 다시 계산합니다. 추가 AI 요청 없이 미리보기와 다운로드 파일을 함께 갱신합니다. `픽셀·색상 조정은 추가 생성 없이 적용돼요.`라고 안내합니다. `원본 색상`은 업로드 원본이 아니라 픽셀화 직전 AI 결과의 색상을 유지한다는 뜻입니다.
- `PNG 다운로드`는 파일을 바로 저장하고, 파일명은 `suminpixel-YYYYMMDD-HHmmss.png` 형식을 사용합니다.
- `다시 만들기`는 입력 카드로 이동해 초점을 제공합니다. 이 버튼 자체로 유료 AI 요청을 자동 실행하지 않습니다. 사용자가 생성 버튼을 눌러야 새 요청이 시작됩니다.
- 같은 입력으로 다시 생성하더라도 AI가 같은 그림을 보장하지 않는다는 설명을 도움말로 제공합니다.
- 새 생성이 실패하면 이전 성공 결과와 다운로드 기능을 유지하고, 새 실패 메시지만 별도 표시합니다. 현재 입력 설정과 이전 결과의 설정이 다르면 결과 아래에 이전 생성 시점의 픽셀 크기·색상 수를 표시합니다.

### 4.4 피드백 영역

제목은 `SUMINPIXEL은 어땠나요?`이고 안내는 `로그인 없이 의견을 남겨 주세요. 작성한 내용은 아래 목록에 공개됩니다.`입니다. 이 영역은 생성 결과 유무와 상관없이 사용할 수 있어야 합니다.

1. `닉네임 (선택)` 한 줄 입력과 20자 제한 안내를 둡니다. 비워 두면 `익명`으로 표시합니다.
2. `피드백` 여러 줄 입력과 `0 / 500` 글자 수를 둡니다. 앞뒤 공백을 제거한 뒤 유니코드 코드 포인트 기준으로 셉니다. JavaScript에서는 `Array.from(text.trim()).length`를 사용해 서버의 기준과 맞춥니다. 공백만 있는 내용은 받지 않습니다.
3. 최신 AI 결과와 사용한 프롬프트를 자동으로 첨부하고 미리보기에서 함께 보여 줍니다. `첨부 빼기`로 텍스트만 제출할 수 있습니다. 동의 체크박스는 처음에는 해제하고 첨부가 선택되어 있으면 이미지와 프롬프트도 공개된다고 명시합니다.
4. 개인정보를 쓰지 않도록 `전화번호, 이메일 등 개인정보는 적지 말아 주세요.`를 보여 줍니다.
5. 제출 버튼은 `피드백 보내기`, 처리 중에는 `보내는 중…`입니다.
6. 저장 성공 응답을 받은 뒤에만 `피드백이 등록됐어요.`를 표시하고 폼을 비웁니다. 실패하면 입력 내용을 유지합니다.
7. 목록은 `최신 피드백` 아래에 닉네임, 날짜, 내용과 공개된 첨부를 표시합니다. 피드백 본문과 프롬프트는 일반 글자로 표시합니다.
8. 최초 20개를 최신순으로 가져오고 `더 보기`로 다음 20개를 아래에 덧붙입니다. 마지막까지 모든 피드백에 도달할 수 있어야 합니다. 첫 20개로 목록을 끝내지 않습니다.
9. 글이 없으면 `첫 번째 피드백을 남겨 주세요.`를 표시합니다. 불러오기 실패는 빈 목록과 구분해 `피드백을 불러오지 못했어요.`와 `다시 불러오기` 버튼을 표시합니다.
10. 전송 직후 목록 새로고침에 실패해도 저장 성공을 실패로 바꾸지 않습니다. `등록됐어요. 목록을 다시 불러와 주세요.`로 상태를 나눠 알립니다.

피드백 날짜는 서버가 저장한 시각을 이용해 `2026. 11. 11. 14:30`처럼 한국 시간으로 표시합니다. HTML의 `time` 요소에는 원본 ISO 시각을 넣습니다. 새 글을 성공적으로 등록하면 목록을 첫 페이지부터 다시 조회합니다. 이미 읽던 더 보기 상태가 초기화된다는 점은 추가 확인창 없이 처리합니다.

## 5. 반응형 배치

| 화면 너비 | 배치 |
| --- | --- |
| 1024px 이상 | 바깥 여백 32px, 입력·결과 2열, 열 간격 24px, 카드 내부 여백 24px |
| 768–1023px | 바깥 여백 24px, 입력·결과 1열, 카드 간격 24px |
| 767px 이하 | 바깥 여백 16px, 1열, 카드 내부 여백 16px, 소개 위아래 간격 32px |

- 데스크톱 1440px와 모바일 375px를 기준 화면으로 검증합니다. 320px에서도 가로 스크롤이 생기지 않아야 합니다.
- 2열일 때 입력과 결과는 위쪽을 맞춥니다. 카드 높이를 강제로 같게 만들어 큰 빈 공간을 만들지 않습니다.
- 작은 화면에서는 입력 → 결과 → 사용 방법 → 피드백 순서를 그대로 유지합니다.
- 탭은 너비를 반씩 사용합니다. 옵션은 공간이 부족하면 다음 줄로 내려갑니다.
- 다운로드와 다시 만들기 버튼은 모바일에서 한 줄에 무리하게 넣지 않고 세로로 배치합니다.
- 피드백 내용은 `overflow-wrap: anywhere`와 `white-space: pre-wrap`을 적용합니다.
- 고정 하단 버튼이나 팝업이 본문과 키보드 조작을 가리지 않도록 구현합니다.

## 6. 상태와 오류 표시

입력 오류는 해당 필드 바로 아래에, AI·네트워크 오류는 생성 버튼 아래의 알림 영역에 표시합니다. 오류가 발생했다고 페이지 전체를 비우지 않습니다. 서버가 반환한 원문, 내부 경로, 비밀 키는 화면에 출력하지 않습니다.

| 상황 | 사용자에게 보일 문구와 행동 |
| --- | --- |
| 이미지 미선택 | `먼저 이미지를 선택해 주세요.`; 파일 선택 버튼으로 초점 이동 |
| 지원하지 않는 파일 | `PNG, JPG, WEBP 이미지를 선택해 주세요.`; 기존 정상 입력 유지 |
| 이미지 크기·용량 초과 | API가 정한 제한을 숫자로 알려 주고 `더 작은 이미지를 선택해 주세요.` 표시 |
| 프롬프트 없음 | `만들고 싶은 장면을 적어 주세요.`; 프롬프트 입력으로 초점 이동 |
| 글자 수 초과 | 해당 필드의 정해진 최대 글자 수를 표시; 초과 값 전송 금지 |
| AI 생성 중 | 중복 요청 방지를 위해 생성 버튼과 생성 입력 비활성; 피드백 영역은 사용 가능 |
| AI 거절 | `이 요청으로 이미지를 만들 수 없어요. 내용을 바꿔 다시 시도해 주세요.` |
| 요청 제한 | `잠시 요청이 많아요. 안내된 시간 뒤 다시 시도해 주세요.`; 서버의 재시도 가능 시각 표시 |
| 시간 초과 | `생성 시간이 길어져 요청을 마쳤어요. 다시 시도할 수 있지만 이전 요청 비용이 발생했을 수 있어요.`; 자동 재요청 금지 |
| 네트워크 단절 | `연결을 확인한 뒤 다시 시도해 주세요.`; 입력·기존 결과 유지 |
| 서버 설정 누락 | `현재 이미지 생성 기능을 준비 중이에요.`; 관리자용 비밀 설정값 출력 금지 |
| 피드백 공백·공개 미동의 | 해당 필드 또는 체크박스 아래에 원인 안내 |
| 피드백 저장 실패 | `저장하지 못했어요. 작성한 내용을 유지했으니 다시 시도해 주세요.` |
| 피드백 더 보기 실패 | 기존 목록 유지, 더 보기 자리에서 재시도 가능 |
| 다운로드 실패 | `파일을 저장하지 못했어요. 다운로드를 다시 눌러 주세요.`; 결과 유지 |

생성 작업 상태와 피드백 작업 상태는 분리합니다. 생성 중 표시를 이유로 피드백 전송 성공 메시지가 지워지거나, 피드백 목록 실패 때문에 생성 버튼이 멈추지 않게 합니다.

## 7. 접근성과 조작

- 페이지 언어를 `lang="ko"`로 설정하고 제목을 `SUMINPIXEL | 이미지와 상상을 픽셀로`로 지정합니다.
- `header`, `nav`, `main`, `section`, `footer`를 사용합니다. 제목은 H1 한 개, 구역은 H2, 하위 카드 제목은 H3 순서입니다.
- 입력 요소마다 화면에 보이는 `label`을 연결합니다. placeholder를 label 대신 사용하지 않습니다.
- 탭은 `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`와 패널 연결을 구현합니다. 좌우 방향키로 탭 이동, Home/End로 처음/끝 이동, Enter 또는 Space로 활성화하고 활성 탭만 Tab 순서에 둡니다.
- 옵션은 실제 radio와 fieldset/legend로 구현합니다. 색깔 사각형만 클릭하게 만들지 않습니다.
- 파일 첨부는 키보드로 조작 가능한 기본 file input을 사용합니다. 드래그앤드롭만 제공하지 않습니다.
- 오류가 있는 입력에 `aria-invalid="true"`와 오류 설명의 `aria-describedby`를 연결합니다. 폼 제출 오류 때 첫 오류로 초점을 옮깁니다.
- 일반 진행·성공 알림은 `aria-live="polite"`, 즉시 조치가 필요한 오류는 `role="alert"`로 알립니다. 같은 메시지를 반복 발표하지 않습니다.
- 결과 이미지 alt는 `AI로 만든 픽셀 이미지. 64 × 64 격자, 최대 32색.`처럼 실제 설정에 맞게 만듭니다. 빈 상태 장식, 구름, 별은 `aria-hidden="true"`로 숨깁니다.
- 링크와 버튼은 역할에 맞게 사용하고, 아이콘 단독 버튼에는 `aria-label`을 제공합니다.
- `prefers-reduced-motion: reduce`에서는 로딩 외 장식 움직임을 제거합니다. 번쩍임과 자동 재생은 넣지 않습니다.
- 200% 확대에서도 입력·피드백·다운로드 조작이 사라지지 않아야 합니다.

## 8. UI 완료 기준

- [ ] 1440px, 768px, 375px, 320px 화면에서 내용이 겹치거나 잘리지 않는다.
- [ ] 두 탭의 입력, 기본 설정, 빈 상태, 생성 중, 성공, 실패 화면을 모두 구현했다.
- [ ] 결과 파일은 실제 1024 × 1024 PNG이고 미리보기에서 픽셀 경계가 흐려지지 않는다.
- [ ] 성공 결과가 있어도 새 생성 실패 뒤 기존 결과를 다운로드할 수 있다.
- [ ] 피드백의 공개 안내·동의·글자 수·저장 성공/실패·빈 목록·더 보기가 있다.
- [ ] 21개 이상의 피드백에서 다음 페이지를 읽을 수 있고, 정렬이 최신순이다.
- [ ] 키보드만으로 탭 변경, 첨부, 입력, 설정, 생성, 다운로드, 피드백 전송이 가능하다.
- [ ] 색 대비, 초점, 스크린리더 알림, 200% 확대를 확인했다.
- [ ] 참조 이미지의 자산을 복제하지 않고 보라·핑크·민트와 픽셀 구성의 분위기를 반영했다.

실제 구현 검증은 [테스트와 완료 기준](06-testing-deployment.md)의 시나리오와 함께 진행합니다. 이 문서 패키지 작성만으로 위 구현 검증이 완료된 것은 아닙니다.
