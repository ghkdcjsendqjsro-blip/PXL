# 프런트엔드 기능 구현

이 문서는 브라우저에서 입력을 받고, AI 응답을 실제 픽셀 이미지로 가공하고, 결과를 저장하는 동작을 정한다. 모양은 [UI 지침](02-ui-ux.md), 통신 필드는 [서버 API](04-backend-openai.md)를 따른다. 여기서 Canvas는 이미지를 픽셀 단위로 읽고 그리는 브라우저 기능이다.

## 1. 상태를 분리한다

```text
입력 준비 → 유효성 검사 → 전송·AI 대기 → 픽셀 처리 → 성공
                    └ 실패 ←───────────────┘
```

다음 값을 서로 분리해 관리한다.

- 입력: 현재 탭 `image|prompt`, 원본 File, 정규화 PNG Blob, 추가 설명, 생성 프롬프트.
- 생성: `idle|validating|generating|rendering|success|error`, 요청 번호, AbortController, 오류.
- 결과: 마지막 성공의 AI 소스 이미지, 그 요청에 사용한 프롬프트, 해당 입력의 첨부 미리보기, 격자, 팔레트, PNG Blob, object URL.
- 피드백: 제출 상태, 요청 UUID, 작성 값, 목록, 커서, 조회 상태.

생성 중에는 탭·파일·프롬프트·옵션·생성 버튼을 잠근다. 피드백 폼은 독립적으로 작동한다. 새 생성에 실패해도 마지막 성공 결과를 지우지 않는다. 픽셀 처리가 끝나 새 Blob을 확보한 뒤에만 기존 결과를 교체한다.

## 2. 이미지 입력

`input type="file"`에 `accept="image/jpeg,image/png,image/webp"`를 지정하고 드래그앤드롭도 같은 검사 함수로 연결한다. accept는 선택 보조 장치이며 실제 검증은 별도로 한다.

1. 파일이 정확히 한 개인지 확인한다. 여러 장이면 첫 장을 몰래 선택하지 않고 오류로 안내한다.
2. 원본 용량은 8 MiB 이하, 확장자는 jpg/jpeg/png/webp, MIME은 해당 이미지 형식만 허용한다. MIME이 비어 있거나 다른 경우 오류를 안내한다.
3. 실제 디코딩 후 가로×세로가 20,000,000픽셀 이하인지 확인한다. 0 크기·깨진 이미지·다중 프레임임을 감지한 이미지는 거부한다. GIF·SVG·HEIC는 MVP에서 지원하지 않는다. 예외적으로 브라우저가 애니메이션 여부를 감지하지 못한 WebP/PNG는 디코딩한 정적 한 프레임만 정규화해 보낸다. UI에서 애니메이션 지원으로 안내하지 않는다.
4. EXIF 회전 방향을 반영한다. 브라우저가 자동 적용한 방향을 중복 회전하지 않도록 테스트 사진으로 확인한다.
5. 임시 Canvas를 1024×1024로 만들고 흰색 `#ffffff`로 채운다. 비율 `s=min(1024/w,1024/h)`로 이미지를 가운데 배치한다. 잘라내지 않고 투명 부분도 흰색으로 합성한다.
6. PNG Blob으로 변환하고 2 MiB 이하인지 확인한다. 초과 시 `정사각형으로 변환한 파일이 너무 커요. 더 작은 이미지를 골라 주세요.`를 보여 준다. 반복 압축·해상도 변경을 몰래 하지 않는다.
7. 정규화 미리보기를 표시하고 이름·용량·흰 여백 안내를 함께 보여 준다. 원본 File은 현재 페이지 메모리에만 둔다.

파일 교체·삭제 시 더 이상 사용하지 않는 object URL을 `URL.revokeObjectURL`로 해제한다. 원본 이미지를 외부 이미지 호스팅에 먼저 올리지 않는다. 사용자가 `만들기`를 누르기 전에는 OpenAI와 서버에 보내지 않는다. 검증 실패로 기존 정상 파일이 사라지지 않게 한다.

추가 설명은 선택, trim 후 최대 1,000 코드포인트다. 빈 값이면 서버의 기본 변환 지침만 사용한다. 새 이미지 선택으로 이전 성공 결과를 즉시 삭제하지 않는다.

## 3. 프롬프트 입력

- trim 후 1~1,000 코드포인트를 허용한다. 공백·줄바꿈만 있는 입력은 거부한다.
- 글자 수는 `[...value.trim()].length`로 표시한다. HTML `maxlength`는 UTF-16 기준이므로 그것만으로 이모지 제한을 구현하지 않는다.
- 예시 버튼은 `보라색 밤하늘 아래 고양이 카페`, `작은 우주선과 민트색 행성`, `딸기 케이크를 든 픽셀 토끼` 같은 문구를 입력란에 채운다. 예시 클릭으로 API를 호출하지 않는다.
- 탭 전환 시 각 탭의 입력은 유지한다. 현재 탭만 API 요청에 포함하고 비활성 탭의 파일·프롬프트는 보내지 않는다.

## 4. 생성 요청

두 모드 모두 `FormData`를 사용해 `POST /api/generate`로 보낸다. `mode`, `prompt`와 이미지 모드의 `image` 필드만 사용한다. grid/palette는 클라이언트 처리값이므로 AI API 요청에 넣지 않는다. `Content-Type` 헤더를 직접 지정하지 않아 브라우저가 multipart 경계를 설정하게 한다.

1. 클라이언트에서 입력을 검사한다. 잘못된 필드에 오류·초점을 제공한다.
2. 생성 상태를 잠그고 요청 번호를 증가시킨다. 이벤트가 두 번 연결되지 않게 한다.
3. `fetch`와 AbortController를 사용하고 110초에 브라우저 대기를 종료한다. 실제 진행률이 없으므로 가짜 퍼센트를 표시하지 않는다.
4. 성공 JSON의 `imageBase64`, `mimeType`, `width`, `height`를 확인하고 이미지를 디코딩한다. `mimeType`은 `image/png`, API 소스 크기는 512×512여야 한다. 잘못된 응답은 일반 오류로 처리한다.
5. 아래 픽셀 파이프라인을 실행한다. PNG Blob까지 생성되면 미리보기와 다운로드를 함께 교체한다.
6. `finally`에서 잠금을 해제한다. 요청 번호가 현재 작업과 다른 오래된 응답은 화면에 반영하지 않는다.

오류 응답이 HTML이거나 JSON 파싱에 실패해도 화면이 깨지지 않게 한다. Vercel 자체의 413·504 응답도 안전한 한국어 오류로 바꾼다. 네트워크 오류·AI 오류를 자동으로 다시 호출하지 않는다. 브라우저 중단은 외부 AI 연산과 비용의 취소를 보장하지 않는다.

## 5. 실제 픽셀 변환 알고리즘

AI에 픽셀 아트 스타일을 요청한 후 **실제 정수 격자**로 다시 처리한다. AI가 반환한 픽셀 느낌만으로 격자 기준을 충족했다고 간주하지 않는다.

### 5.1 격자 축소

선택한 `N`은 32, 64, 128 중 하나다. AI 소스를 N×N Canvas에 `drawImage`로 축소한다. 축소에서는 `imageSmoothingEnabled=true`, `imageSmoothingQuality="high"`를 사용한다. 여기서는 작은 이미지의 대표 색상을 얻는 것이 목적이다. 이 축소 결과를 다음 팔레트 단계에 넣는다.

### 5.2 색상 수 제한

- `original`: N×N 축소 결과의 RGB를 그대로 유지한다.
- `16`, `32`: 아래 결정적 median-cut 방식으로 최대 K색에 매핑한다. 같은 입력·옵션에서 같은 출력이 나와야 한다.

구현 규칙:

1. 축소 이미지의 RGB별 출현 횟수를 집계한다. 투명도는 흰 배경 합성 후 모두 255다.
2. 고유색이 K개 이하면 그대로 사용한다. 그보다 많으면 모든 색을 하나의 상자에 넣는다.
3. 아직 나눌 수 있는 상자 중 RGB 최댓값-최솟값이 가장 큰 상자를 고른다. 동률이면 전체 출현 횟수가 큰 상자, 그다음 생성 순서가 빠른 상자를 고른다.
4. 가장 범위가 큰 채널로 정렬한다. 채널 동률은 R→G→B, 같은 채널값의 색은 RGB 사전순이다. 출현 횟수의 누적 중앙값에서 양쪽이 모두 비지 않도록 분리한다.
5. K개 상자 또는 더 나눌 수 없을 때까지 반복한다. 각 상자의 가중 평균 RGB를 반올림해 대표색으로 만든다. 중복 대표색은 합친다.
6. 각 픽셀을 RGB 제곱거리 최소인 대표색으로 바꾼다. 거리 동률은 RGB 사전순으로 선택한다. 디더링은 넣지 않는다.

`16색`은 최대 16개 고유 RGB라는 뜻이다. 간단한 그림은 더 적을 수 있다. 이미 그려진 최종 PNG를 다시 축소해 누적 처리하지 말고 항상 원래 AI 소스부터 다시 계산한다.

### 5.3 선명한 확대와 파일 생성

출력 Canvas는 항상 1024×1024다. `imageSmoothingEnabled=false`를 지정한 뒤 N×N Canvas를 1024×1024로 확대한다. N별 정수 배율은 32→32배, 64→16배, 128→8배다. 출력은 불투명 PNG이며 모든 논리 픽셀은 같은 색의 정사각 블록이어야 한다.

```javascript
output.width = output.height = 1024;
const ctx = output.getContext('2d');
ctx.imageSmoothingEnabled = false;
ctx.drawImage(logicalCanvas, 0, 0, 1024, 1024);
// toBlob callback에서 null을 검사한 뒤 성공 Blob을 보관한다.
```

미리보기에는 이 출력 Blob의 object URL을 쓴다. 다운로드를 누를 때 다른 파이프라인을 돌려 미리보기와 다른 파일을 만들지 않는다.

## 6. 결과와 재조정

- 이미지 모드에서는 해당 성공 요청에 사용한 첨부 미리보기와 결과를 `원본`·`픽셀 결과` 버튼 또는 두 썸네일로 확인할 수 있게 한다. 결과 이미지는 정규화된 원본과 동일해진다고 약속하지 않는다.
- 성공 후 N 또는 팔레트를 바꾸면 보관한 AI 소스에 즉시 재적용한다. 연속 변경은 마지막 설정만 화면에 반영한다. 네트워크 요청 수가 0인지 확인한다.
- 새 파일·프롬프트 입력은 결과의 입력 이력을 바꾸지 않는다. 결과 카드에는 현재 결과에 실제 적용된 옵션을 표시한다.
- `PNG 다운로드`는 현재 Blob을 `<a download>`로 저장한다. 파일명은 한국 시간 기준 `suminpixel-YYYYMMDD-HHmmss.png`다. 원본 파일명이나 프롬프트를 파일명에 넣지 않는다.
- 다운로드를 즉시 지원하지 않는 브라우저에서는 PNG를 새 탭에서 열어 저장하도록 안내한다. 결과 소멸이나 새 AI 요청으로 대체하지 않는다.
- `다시 만들기`는 입력 영역으로 이동할 뿐 API를 호출하지 않는다.
- 생성 결과·입력 이미지는 localStorage, IndexedDB, 쿠키에 보관하지 않는다. 새로고침 또는 페이지 종료 시 사라진다는 안내를 표시한다.

## 7. 피드백 화면 연결

상세 API와 정렬 계약은 [Supabase 지침](05-supabase-feedback.md)을 따른다.

- 닉네임·내용·공개 동의를 검사한 뒤 사용자 제출 단위 UUID를 만든다.
- 새 AI 결과가 완성되면 해당 요청에 사용한 프롬프트와 렌더링한 1024×1024 PNG를 첨부 후보로 둔다. 사용자가 `첨부하기`를 누르면 두 항목을 함께 선택하고, `첨부 빼기`를 누르면 선택을 해제한다. 새 AI 결과가 완성되거나 피드백 전송이 성공하면 첨부 선택을 해제한다. 첨부가 선택되면 이미지와 프롬프트 공개를 동의 문구에 명시한다.
- 전송이 실패하면 내용을 유지한다. 저장 여부가 불확실한 재시도는 같은 UUID·같은 내용과 첨부로 보낸다. 내용이나 첨부를 바꾸면 새 UUID를 만든다.
- 저장 성공 응답 후에만 폼을 초기화하고 목록 첫 페이지를 다시 조회한다.
- 저장 성공과 목록 실패는 다른 상태로 표시한다. 목록 실패를 이유로 이미 성공한 POST를 다시 보내지 않는다.
- 목록은 20개씩 가져와 마지막까지 `더 보기`로 읽게 한다. 커서 초기화·ID 중복 제거·더 보기 실패 시 기존 목록 유지가 필요하다.
- 피드백 본문과 첨부 프롬프트는 `textContent`로 표시한다. 첨부 이미지는 같은 출처의 피드백 이미지 API에서 불러온다. 날짜는 `Intl.DateTimeFormat('ko-KR', {timeZone:'Asia/Seoul', ...})`로 표시한다. 커서에는 포맷된 날짜가 아닌 API 원본을 사용한다.
- 봇용 `website` 입력은 시각·키보드·스크린리더에서 제외하고 정상 전송 시 빈 문자열을 보낸다. 자동완성도 끈다.

## 8. 프런트엔드 완료 기준

- [ ] 이미지 파일의 크기·종류·해상도와 프롬프트·피드백 길이를 전송 전에 검사한다.
- [ ] 이미지 첨부·글 입력이 각각 맞는 API 모드로 연결된다.
- [ ] 연속 생성 클릭은 한 요청만 만든다. 110초 중단과 비JSON 오류를 처리한다.
- [ ] 32·64·128 격자와 원본·16·32색의 9개 조합이 실제 결과에 반영된다.
- [ ] PNG는 1024×1024, 불투명, 지정 격자 경계가 선명하고 팔레트 상한을 지킨다.
- [ ] 옵션 변경 때 API 호출이 없고, 실패 때 기존 결과를 저장할 수 있다.
- [ ] 피드백 저장·전체 목록·빈 상태·더 보기·오류 상태를 실제 API와 확인했다.
- [ ] 파일 교체와 결과 변경 때 사용하지 않는 object URL을 해제한다.
